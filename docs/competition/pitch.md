## 一、3 分钟开场（可直接照读）

> 我先说一个大家在自己实验室都见过的画面。
>
> 一台八卡的 A800，两张在跑别人的长训练，六张空着。你想塞一个微调进去，但你不敢——因为卡是共享的，
> 主人回来时你要是没清干净，就是事故。于是所有人宁愿排队等"整台机器空闲"，六张卡空转到天亮。
>
> GPU Scavenger 解决的就是这六张卡**敢不敢用**的问题。它插在中间做一层控制平面：
> 主人装一个 Agent 说"这几张可以借"，任务进来跑在 Agent 自己的内核级隔离边界里；
> 主人回来——他点一下 Claim，或者他的进程开始占卡被观测到——Agent **只驱逐自己启动的进程**，
> 然后验证显存真的回到基线了，才把卡交还。没跑完的分片无损回队，去别人的空闲卡上继续。
>
> 这里最关键的一点是：我们把"进程退出"和"显存可用"**拆成了两个状态**。
> 社区惯例是进程没了就当卡还回来了，但 CUDA context 还在、NVML 还报着几百 MiB，
> 下一个任务撞上的是脏显存，主人看到的是"你的工具把我的卡搞坏了"。
> 所以我们要求三项物理判据——cgroup 为空、自有 GPU 进程为零、显存回到启动基线 ±64 MiB——
> **并且连续两次采样都满足**，才签发 ReleaseVerified。
>
> 在实验室那台八卡 A800 上实测：从 Claim 激活到自有 scope 消失 **339 毫秒**，
> 到显存回到基线 **472 毫秒**，复测 470。派生进程树那种 `fork` 加 `setsid` 逃管的子进程，328 毫秒一并回收，
> 全程没有触碰任何一个外部 PID。
>
> 部署侧是零侵入：不改训练代码、不上 K8s、单包 5.95 MB，节点只需要能主动往外建一条 TLS 连接。
>
> 作品已经用 Qoder Sites 发布成公开访问，评委现在就可以打开，
> 里面第 06 节是一个八卡演练台，**它跑的状态机和释放判据跟开源实现是同一份代码**，
> 你可以亲手按下 Claim，看着 472 毫秒这条链路走完。

（现场动作：切到演练台，点「4 卡并发 + 宿主 472ms 抢占」，再点「激活宿主 Claim」，让事件日志走完。）

## 二、五条亮点（每条一句话 + 一个证据）

1. **释放是可验证状态，不是一次性动作。**
   证据：`scavenger-core/src/release.rs` 的纯函数判据 + 472/470ms 两轮实测。

2. **宿主优先由身份门禁保证，而不是靠配置约定。**
   证据：七元组（含 `cgroup_id` 与 `process_start_time` 防 PID 复用）；
   fork/setsid 派生树 328ms 完整回收，外部 PID 一个没动。

3. **零侵入：能进实验室，而不是只能进数据中心。**
   证据：出站 gRPC + enrollment token，5.95 MB 单包，无 K8s/Slurm/Docker，不改训练脚本。

4. **不确定就不借：能力上报驱动的 fail-closed。**
   证据：Windows/ROCm/MIG 切分上报 `schedulable=false`，调度器直接跳过；
   探针失败进 Degraded/Quarantined 同样停调度。宁可少借一张卡，不在没验证的边界上赌宿主安全。

5. **同一份判据代码同时服务真机、单测和浏览器演练台。**
   证据：L0 零 I/O；评委在浏览器里按的 Claim 与真机跑的是同一套语义——页面数字不是特效。

## 三、十二个预判提问

**Q1：472ms 是 p95 吗？样本量多少？**
不是 p95。是两轮 T_release 实测（472 / 470ms）和三轮 T_task_exit（339 / 328 / 347ms）。
设计目标才是 p95 ≤1500ms，实测余量 3.18 倍。样本量确实小，要报 p95 需要更长压测，这是下一步。
**（别硬撑 p95，承认样本小比被追出来更稳。）**

**Q2：页面上 78.4% 利用率、~21% 基线是怎么测的？**
这两个是场景推演口径，没有实测来源，我们在仓库里明确标成"待补"。
能算的是：按真实全机快照，五张空闲卡补到宿主水位约 88%，卡数口径是 5/8 = 62.5%。
要坐实 78.4% 需要一段跨天的 DCGM 采样。
**（这题答好的加分比答坏扣分多——主动区分实测和推演，正是工程完成度的证据。）**

**Q3：为什么不直接用 K8s device plugin 或 Slurm？**
它们是正确的数据中心方案，但前提是先纳管节点。实验室的现实是十几台各自为政的机器，
主人不同意装集群 Agent，也没人运维。我们要的是"今天就能把闲卡并网"，所以把侵入成本压到单包 + 出站连接。
真要接进集群，L0 的判据和身份模型可以直接搬。

**Q4：误杀宿主进程怎么办？你们真验证过吗？**
按进程名杀是事故源，所以判定走七元组，任何一项对不上就只读观测、永不发终止。
真机验证过两类：普通 CUDA hold（339ms）和 `fork` + `setsid()` 逃管子进程（328ms，
两个 PID 都在同一 `cgroup.procs` 里被一并回收）。验收记录里明确写了没有对任何外部 PID 执行操作。

**Q5：显存回到 ±64 MiB 就算释放，会不会残留影响下一个任务？**
64 MiB 是容差不是目标值。实测里 GPU2 是回到 2 MiB 基线本身。
之所以留容差，是因为宿主侧可能有别人的小分配在动，判据必须能区分"我留下的"和"别人新占的"——
这也是七元组里 `device_uuid` + `uid` + `cgroup_id` 联合作用的一部分。

**Q6：主人不点 Claim 呢？谁替他主张优先权？**
三条路：显式 Claim（按钮/文件）、配置的 Guard 观测到外部占用自动触发、
以及只读探针识别 `ObservedExternal`。第三种是"主人什么都没做，只是他的训练进程开始占卡"，
Agent 也会停止领取新任务并让路。

**Q7：断线了任务会不会丢？**
不丢，至少一次语义。Agent 有界重连（250ms→5s），重连时先停掉自己的 scope；
新 Hello 触发把该 Agent 的 leased/running 回收，未提交分片 `lease_epoch` 复位回 Queued。
真机验证过：Controller 停止期间 GPU2 约 3–4 秒回到 2 MiB，重启后任务回 queued 且没有重复启动，
事件表只有一条 Started。幂等提交保证结果不会重复写入。

**Q8：checkpoint 是通用能力吗？任意训练任务都能无损续跑？**
不是。checkpoint 需要任务配合——`SIGUSR1` 触发、写 `GPU_SCAVENGER_CHECKPOINT_PATH`、原子 rename、回 SHA-256 ACK。
真机验证的是本项目自己的 helper（37 字节产物 + digest 记录）。
**任意第三方训练框架的恢复兼容性属于未验证项**，当前是 fail-closed，不说它支持。

**Q9：安全吗？谁能提交任务、谁能占卡？**
节点侧主人决定贡献哪几张卡（device UUID 白名单）和策略（ObserveOnly/Cooperative/Strict）；
Agent 侧 enrollment token 准入，错误 token 被拒；控制面可选 mTLS，证书轮换用 SIGHUP 且不强杀长连接。
需要说明的是：验收证书和 token 只在独立 smoke 目录，**生产部署还需要正式 PKI 与 enrollment 流程**，这条我们写在限制里。

**Q10：多 Master、多节点故障恢复做了吗？**
没有。多 Master 和跨节点故障恢复是未验证项，当前 fail-closed。
多 Agent 调度在本地 Controller 测试里验证过两个 Agent 的 round-robin 与不重复 lease；
远端只用了 GPU2，没有为了演示去占用别人的共享卡，所以我们不宣称多节点恢复。

**Q11：Qoder 具体做了什么，你做了什么？**
先说清楚：**整个项目是我用 Qoder 从头实现的**——仓库从 baseline commit 起 26 个提交，
`crates/` 4,992 行 Rust（五个 workspace 成员、0 unsafe）、`site/` 9,318 行 TS（38 个文件）、
proto、21 个单测、CI 与打包、真机验收脚本和站点发布，都是在 Qoder 会话里写出来的，没有一行来自模板。
Qoder 负责写代码、跑门禁（fmt / clippy -D warnings / test 循环到全绿）、开无头浏览器逐板块验证、
连远端编排真机验收、自己走完 Qoder Sites 发布，还自己把赛题页渲染出来读了硬性要求。
我盯的是三件事：产品契约（宿主优先、释放必须可验证）、模块边界（判据必须是 L0 纯函数，
否则页面数字就是假的）、以及归因纪律——比如它一度把 GPU6 在会话期间被外部改变的水位写进本项目成果，
我要求改成"不归因于本项目"；它查出页面三个数字无出处后动手改了页面，我叫停并要求逐条回滚、改出口径文档。
3D 那块是我逼着反复迭代的，第一版就是个贴了 logo 的盒子。

**Q12：这东西有人真的在用吗？**
目前是实验室自用 + 可复现的真机验收，不是生产集群。
所以我们的说法是：核心闭环有实测证据，规模化和多节点是路线图。
（如果被追问用户数，直接说没有外部用户，别编。）

## 四、收尾（30 秒）

> 这个项目我们唯一不敢含糊的地方，是"还卡"这两个字。
> 借出去不难，难的是主人回来的时候，你能证明你确实干净地还回来了。
> 所以我们把这件事做成了一个可验证的状态，339 毫秒清空边界，472 毫秒归还显存，
> 全程只碰自己启动的进程。
> 作品已经公开部署，评委现在就可以打开，亲手按下那个 Claim。
